# Languages

Locale comes from the URL. `/` is English; the other prerendered copies use `src/routes/[[lang=locale]]` and the matcher in `src/params.ts`. Do not redirect based on `Accept-Language`: pages are prerendered and the worker serves only `/api/*`, so nothing server-side can pick the locale. `src/lib/components/LanguagePicker.svelte` lets visitors choose a language and shows returning visitors a dismissible prompt stored in localStorage as `activeyear.locale`.

Strings live in typed catalogs at `src/lib/i18n/messages/<locale>/<namespace>.ts`. English defines the shape; other locales are typed as `typeof en`, so `pnpm check` catches missing keys. Components read `i18n.m` and `i18n.locale` from `#lib/i18n/i18n.svelte.js`; plain TypeScript uses `messages(locale)`. The root layout awaits `loadMessages`, so other catalogs load only on a language switch. Code outside a page render, such as a `+server` endpoint, awaits `loadMessages`. Search sport names and picker suggestions come from the small `SPORT_NAMES` and `PICKERS` tables. Use `plural(locale, n, { one, other })` for plurals. Keep phrases with values as whole functions, never glued fragments, because word order differs between languages.

Number and date formatting takes a `locale` and uses `INTL_LOCALES`. Unit suffixes (`km`, `mi`, `m`, `ft`, `kcal`, `h`, `m`, `s`) stay the same in every language. Parsing stays independent of the UI language: parsers keep English messages for logs, and the UI maps error types to translated text.

Export parsing accepts Garmin and Strava files in English, Spanish, German, French, Italian, Dutch and Portuguese using header and activity-type tables in `src/lib/parsers/garminLocales.ts` and `stravaLocales.ts`. Garmin files carry no unit marker, so imperial accounts rely on the Metric/Imperial choice on the upload screen. It starts on Metric in every region, and so does the dashboard's km/mi toggle. After a Garmin CSV loads, the dashboard unit follows the choice.

Translations must fit the cards; see Translations in `docs/DESIGN.md`.

## Add a Language

1. Add the code to `LOCALES`, `LOCALE_NAMES`, `INTL_LOCALES`, and `OG_LOCALES` in `src/lib/constants/locales.ts`.
2. Copy `src/lib/i18n/messages/en/` to the new locale, translate the strings, type each namespace as `typeof en`, register its loader in `src/lib/i18n/messages/index.ts`, and add it to `src/lib/i18n/messages/sports.ts` and `src/lib/i18n/messages/picker.ts`.
3. Check that the fonts cover the script. The layout loads only the `latin` and `latin-ext` subsets of the theme fonts (`THEME_FONT_FAMILIES`), which cover every letter of the current languages but no Cyrillic, Greek or CJK. None of them has U+202F (the narrow no-break space French uses as a thousands separator and before %) or the → arrow in the export guides. A missing character comes from a fallback font whose width differs per browser, so `localeNumber` in `utils/format.ts` swaps U+202F for U+00A0, which every theme font has. The arrow still comes from the system fallback font. RTL languages also need layout work.
4. Run `pnpm check` to catch missing keys, then inspect all three cards in the new language.
